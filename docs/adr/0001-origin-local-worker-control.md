# ADR 0001：Origin 由本机 Codex Worker 控制

## 状态

已接受

## 背景

工作台采用 Codex-only 架构，当前已有本机 Worker、任务队列和“连接与恢复”页面。Origin2024 安装在用户电脑上，需要接入科研流程，但用户尚未确定具体研究对象、数据格式和分析方法。

## 决策

Origin 的控制入口放在本机 Codex Worker。网页通过已有 Codex 任务接口提交请求，Worker 在本机调用 Origin 桥接；网页不直接控制桌面进程，也不新增外部模型或云端 Agent。

第一阶段只实现 Origin 安装检查和无害 smoke test。Origin 以可见窗口运行，测试写入独立临时目录，原始数据和正式 `.opju` 工程只读，所有操作写入结构化日志。

## 备选方案

- 浏览器直接调用 Origin：无法安全访问桌面进程，也会破坏现有本地边界。
- 网页后端控制 Origin：Origin 在用户电脑上，服务器无法可靠获得该进程和许可证。
- 一开始支持任意 Origin 脚本：在研究目标和数据格式未知时风险过高，难以验证。

## 后果

- 可以复用现有 Codex Worker 的认证、队列、状态和失败重试。
- 第一版不依赖具体科研分析方法，后续可逐步增加数据导入、拟合和图表导出。
- Origin 必须安装并可由当前 Windows 用户启动；Worker 离线或许可证不可用时，工作台必须显示可读错误。
