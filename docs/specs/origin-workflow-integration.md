# Origin 科研流程接入 Spec

## Problem Statement

工作台已经能记录任务、文献、每日记录、研究地图和 Codex 周复盘，但还不能把用户电脑上的 Origin2024 纳入科研工作流。用户目前尚未确定具体研究方向和分析方法，因此第一版不应假设某种实验、数据格式或统计模型；需要先建立一条安全、可观察、可恢复的本机控制链路。

## Solution

在现有本机 Codex Worker 中增加 Origin 桥接能力。工作台通过现有 Codex 任务队列提交 Origin 检查任务，Worker 在本机以可见窗口启动 Origin2024，执行白名单中的 `check` 或无害 `smoke-test`，将状态、耗时、版本、临时目录和可读错误回传到工作台。

“连接与恢复”页面增加 Origin 状态卡片；Agent 浮窗可以提交“检查 Origin 连接”任务。第一版不导入正式数据、不修改正式工程、不生成科研结论，也不接入外部服务。

## User Stories

1. 作为研究生，我想知道 Origin2024 是否被工作台识别，以便开始数据分析前确认工具可用。
2. 作为研究生，我想从 Agent 浮窗提交 Origin 检查，以便不离开科研工作流。
3. 作为研究生，我想从命令行执行 Origin 检查，以便排查 Worker 或桌面权限问题。
4. 作为研究生，我想看到检查任务的排队、运行、成功和失败状态，以便知道当前是否可以继续。
5. 作为研究生，我想看到可读的失败原因，以便区分未安装、无法启动、许可证不可用和 Worker 离线。
6. 作为研究生，我想让 Origin 以可见窗口运行，以便在早期验证阶段观察它的行为。
7. 作为研究生，我想确保测试不覆盖原始 Excel、CSV 或 `.opju` 工程，以便避免数据损失。
8. 作为研究生，我想让测试文件写入独立临时目录，以便清理测试痕迹并保持正式项目目录干净。
9. 作为研究生，我想查看最近一次 Origin 检查时间和结果，以便判断连接状态是否过期。
10. 作为研究生，我想让失败任务可以重试，以便修复 Origin 或 Worker 后继续验证。
11. 作为研究生，我想让连接测试日志保留命令、版本、耗时和错误摘要，以便复盘本机环境问题。
12. 作为研究生，我想让 Origin 控制继续沿用当前工作区和项目隔离，以便不同项目不会混用任务状态。
13. 作为研究生，我想让第一版不要求我先决定具体实验方法，以便入学前也能先搭好工具链。
14. 作为研究生，我想让后续的数据导入、拟合和图表输出可以关联研究地图，而不必重新建设另一套 Agent 系统。

## Implementation Decisions

- 使用已有 Codex Job 生命周期作为唯一任务边界：`queued → running → completed/failed`。
- Origin 桥接运行在本机 Worker 进程中，不在 FastAPI 服务端执行桌面自动化。
- Origin 安装发现优先识别 Origin2024，并允许通过环境变量覆盖可执行文件路径；不把路径写入前端。
- 第一版桥接只暴露两个白名单动作：`check` 和 `smoke-test`。
- `check` 只报告安装路径、版本和可启动性；`smoke-test` 在独立临时目录创建最小测试工程并执行无害响应检查。
- Origin 以可见窗口启动；第一版不支持隐藏运行、任意脚本和任意命令注入。
- 原始文件只读；桥接不得写入用户提供的原始目录，不覆盖已有工程。
- 所有临时文件使用唯一目录并在日志中记录目录标识；清理失败只产生警告，不影响结果判断。
- 结构化结果至少包括动作、状态、Origin 版本、耗时、临时目录、错误代码和可读错误摘要。
- “连接与恢复”页面新增 Origin 状态，不改变现有数据库恢复流程。
- Agent 浮窗只提交 Origin 检查任务，不直接执行桌面命令。
- 后续分析运行应保存原始数据引用、参数、Origin 工程、导出物和研究地图关联；本 spec 不实现这些字段。

## Testing Decisions

测试只通过三个公共 seam：

1. 工作台 Codex Job API：验证 Origin 检查任务创建、状态变化、结果和失败重试。
2. 本机桥接 CLI：验证 `check` 和无害 `smoke-test` 的外部行为，不测试 Origin 内部 COM 对象。
3. 连接与恢复页面：验证 Origin 状态、最近检查时间和错误摘要展示。

必须覆盖：

- 找到 Origin2024 并报告版本。
- Origin 不存在或不可启动时返回可读失败状态。
- smoke test 不覆盖原始文件，并使用独立临时目录。
- Worker 离线时网页显示离线，不把失败伪装为 Origin 错误。
- 同一项目提交的任务不会出现在另一个项目的列表中。
- 桌面浏览器无控制台错误、失败请求和横向溢出。

不测试具体科研结论、图表美观度、拟合正确性或任意用户脚本；这些属于后续分析运行 spec。

## Out of Scope

- Excel/CSV 正式导入。
- Origin 工程批处理、拟合、统计、图表模板和论文图片导出。
- 任意 Origin C、LabTalk 或 Python 脚本执行。
- 后台隐藏运行和自动关闭用户已有 Origin 窗口。
- 云端 Origin、远程桌面、外部 Agent、AnySearch、SciVerse 或 Zotero 同步。
- 自动生成实验数据、统计结果或研究结论。

## Further Notes

Origin 接入的科研定位是“数据分析工具适配层”，不是新的科研阶段状态机。待用户入学并明确研究方向、数据文件和分析方式后，再单独定义“分析运行”及其证据产物；届时应沿用本地 Worker、研究地图和备份恢复边界。
